# 余烬裂隙扩展包 v18.0.3 → v19 迁移 · 评审交接说明

## 背景

用户有一个《余烬裂隙》网页游戏的内容扩展包，原本基于「憨憨问号改版 18.0.3」底包，
通过一个 618KB 的「末尾移植块」`block_new.js` 在游戏主 IIFE 尾部注入玩法。
官方线上版 https://ember-rift.pages.dev/ 已经升级到 v19，符号全部重新压缩命名，
扩展包无法再直接用。本次任务把扩展包全量迁移到 v19 基底。

## 关键事实（已实测）

- v18.0.3 底包主脚本：1,101,757 字符；v19：1,249,993 字符。
- 两侧顶层符号**位置重合度仅 0.1%**（不同压缩产物），不能按名字直接对齐。
- 两侧都存在「语义导出表」（`N(Module,{KEY:()=>symbol})`），共 1011 个语义名可 100% 对齐。
- 移植块引用 366 个底包全局符号，其中 348 由 symmap 指纹映射，18 由导出表/字符串锚点补齐。
- v19 没有运行时 mod loader；有完善的事件系统（`hit:mods`、`map:stats`、`kill:loot`、`box:open` 等）。
- v19 底包原生暴露 `window.__rift`（Proxy），可访问 1296 个语义导出名。

## 本次改动

| 文件 | 说明 |
|---|---|
| `tools/remap.mjs` | 新建。基于 acorn 的真实词法作用域分析，把移植块里的自由引用重命名到 v19 符号。只改未被本块声明遮蔽的标识符，不碰属性名/字符串。 |
| `build/block_v19.js` | 产出。`block_baseline_18.0.3.js` 经 remap 生成，5524 处替换，语法通过。 |
| `build/expose_v19.js` | 产出。测试/热修 API 桥，72 处替换。 |
| `tools/build-v19.mjs` | 新建。以 v19 为基底的构建脚本，注入点改为「命中才注入」，未命中记录 skipped。 |
| `tools/harness_v19.cjs` | 由原 harness 移植到 macOS：修 jsdom 路径、改为按顺序执行所有 inline 块（原版只执行最后一个，导致 mods 未加载）、修正 hotfix.json 路径、更新 2 条图谱数量断言。 |
| `cheat/cheat/ember-rift-gui.user.js` | 修改器。@match 增加 ember-rift.pages.dev，版本 1.0→1.1。API 层无需改动（v19 的 __rift 提供了所需的全部 22 个接口）。 |

## 验证结果

- 语法门：测试版 2 个 inline 块全部 OK。
- 玩法回归（jsdom，397 条断言）：`RESULT: ALL PASS`。
- 修改器注入：面板挂载、5 个标签页切换、背包读取全部正常，0 报错。
- 构建补丁：应用 10 条，跳过 3 条（逐对象/逐掉落/逐实体循环级 try-catch，因 v19 渲染管线重构、原锚点语义消失而主动不注入）。

## 需要评审关注的点

1. **符号误映射**：`symbol_map_18to19.json` 中 method 为 `export-table` / `exact-canon` / `fingerprint` / `string-anchor` 的置信度差异，以及 medium 置信度条目是否可信。
2. **语义错位风险**：符号名映射正确不代表函数语义未变。v19 只有 259/1274 个函数体与老版完全一致，移植块的 monkey patch 目标函数可能被重构。
3. **被跳过的 3 条加固注入**：会不会导致线上偶发崩溃（吞字/贴图消失）。
4. **remap 的作用域分析**是否有边界漏洞（catch 参数、for-of let、解构、类字段等已处理，是否还有遗漏）。
5. **修改器**改动的正确性与安全性；是否有残留对 18.0.3 行为的假设。
6. **构建产物**是否可独立运行（热修、mods 内嵌顺序是否正确）。
