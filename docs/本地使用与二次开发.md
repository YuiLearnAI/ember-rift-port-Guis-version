## 四、二次开发：三条主线

### 4.1 改玩法（90% 的需求）

```bash
# 1) 改 build/block_v19.js（这就是那个「末尾移植块」）
# 2) 重新出包
npm run build
# 3) 跑门禁，必须全绿
npm run verify        # = check + test + smoke
# 4) 打开 http://127.0.0.1:8787/ 实际玩一把
```

- 移植块被包进 `(function(){ … })()` 塞进主 IIFE 尾部，能直接用底包内部符号。
- 块内引用底包符号时，**用的是 v19 压缩名**（如 `Yt`、`ci`、`Jt`），不是语义名。想知道某个语义名对应谁：查 `out/symbol_map_18to19.json`，或在浏览器控制台用 `__rift.XXX` 探。
- 加新内容表：改 `pack/.../mods/` 下对应 js；若是**新文件**，还要在 `tools/build-v19.mjs` 的 `MOD_FILES` 数组里登记，否则不会内联。

### 4.2 改数值 / 加防崩加固

在 `tools/build-v19.mjs` 里用 `tryPatch(html, 锚点, 替换, 标签)` 加一条：

```js
base = tryPatch(base, "原文锚点", "替换后内容", "my-patch");
```

**关键机制**：锚点找不到时**不报错，只记 skipped**。所以每次 `npm run build` 后必须看输出或 `reports/build-v19-report.json`：

```json
{ "applied": [{"label":"res-cap-server","hits":1}, ...], "skipped": [{"label":"guard:obj-loop","reason":"..."}] }
```

当前基线：**10 条生效 / 3 条主动跳过**（逐对象/逐掉落/逐实体的循环级 try-catch，v19 渲染管线重构后原锚点已不存在，v19 自身有逐项判定兜底）。

> 铁律：如果 `applied` 里某条不是 1 或预期次数，说明底包变了，你的补丁可能打偏。**hits 异常 = 红灯**。

### 4.3 改修改器

```bash
# 改 cheat/cheat/ember-rift-gui.user.js 之后
npm run cheat:review    # 静态审查：语法 / __rift API 是否存在 / 已知坑 / try-catch / XSS 转义
npm run cheat:smoke     # 161 条纯逻辑断言（含界面级 47 条，前提装了 jsdom）
```

改完记得同步 `@version`（当前 1.1），并确认 `cheat/cheat/DESIGN.md` 里的数据调色板/通货分组与新逻辑一致（`smoke.js` 会校验「34 种通货识别色必须登记在 DESIGN.md」这类一致性）。

### 4.4 加回归断言

`tools/harness_v19.cjs` 里已有断言辅助：

```js
const fails = [];
function ok(name, cond, extra) { /* PASS/FAIL 并收集 */ }

// 用法（文件末尾追加即可）
ok("我的新功能：xx 应该 yy", someValue === expected, "实际=" + someValue);
```

跑完看最后一行：`RESULT: ALL PASS` 才算过；有 FAIL 会列出名字并以非 0 退出。

## 五、官方再升版（v19 → vNN）怎么迁

这是本仓库最贵的能力，流程已跑通一次（18.0.3 → v19）：

```bash
# 1. 抓新底包
curl -sSL https://ember-rift.pages.dev/ -o base/vNN-online.html

# 2. 用旧映射资产对新旧底包重算符号映射（生成 v19→vNN 表）
#    参考 tools/remap.mjs 的输入输出：<源块> <映射表> <输出块> <报告>

# 3. 校验映射目标合法性（必须是新底包真实存在的顶层符号）
node tools/verify_map.mjs

# 4. 重映射移植块
node tools/remap.mjs build/block_v19.js out/symbol_map_v19toNN.json build/block_vNN.js out/remap_report.json

# 5. 把 build-v19.mjs 里的 BASE 常量指向 vNN，逐条核对 tryPatch 命中数
npm run build && npm run verify

# 6. 看 skipped 清单：哪些加固锚点失效了，按新底包重写锚点
```

判断工作量：先比「两侧函数体完全一致数」。18.0.3→v19 是 259/1274，属于大重构；若新版本一致性 > 80%，基本可以只改锚点。

## 六、已知限制 / 坑

1. **符号对得上 ≠ 语义对得上**：v19 有 1000+ 函数体被重写，移植块对某些函数的 monkey patch 在边界场景可能行为漂移。397 条断言覆盖主路径，不等于全量回归。
2. **jsdom 的 canvas 是 stub**：所有绘制类问题（贴图错位、吞字、闪烁）只能真浏览器验证。改渲染相关代码后务必真机试。
3. **3 条循环级防崩加固未注入**：理论上某个对象绘制抛异常仍可能中断该帧。长时间刷图观察有没有「突然卡住/贴图消失」。
4. **不要手改产物 HTML**：`npm run build` 会整份重写。
5. **版本号三处一致**：`build-v19.mjs` 的 `VERSION`、发布文件名、`hotfix.json` 的 `version`（构建时自动改写）。改版本要一起改。
6. **`tools/_review_*.mjs|*.cjs`** 是评审阶段的临时脚本，不属于流水线。其中 `_review_repro.mjs` 故意复现的是「修复前」的插入逻辑，它输出 `hotfix 在 main 之前? false` 是预期结果（用来对照磁盘产物 `true`，说明当年的 bug 已修）。别被它吓到。
7. **git 身份未配**：本机全局 `user.name` / `user.email` 为空，`git commit` 前需先设置：

```bash
git config --global user.name "你的名字"
git config --global user.email "you@example.com"
```

8. **大文件资产不在 Git 里**：`base/*.html`、`build/*.html` 由 Release 承载，新克隆要先 `npm run assets:pull`。另外 `build-wiki.mjs` 会把构建时间写进产物，所以自己重建的 Wiki 与 Release 归档哈希不同——这是正常的，`npm run assets:check` 会报 MISMATCH。要字节一致就固定时间：`EMB_BUILD_AT=<归档时间> node tools/build-wiki.mjs`。

npm run wiki          # = wiki:build + wiki:verify（构建后立刻跑运行时验收）

### 7.1 资产与命令

3. **文案纠偏**：官方页两处「宝石最高 20 级」改成 30 级（扩展把等级上限抬到 30）。
4. **移除官方站统计脚本**：官方快照里带 Cloudflare beacon（token 属于官方账号），本副本已剥离，避免把访问算到官方头上。
5. 标题与 meta 描述标注「异界扩展版 / v2.2.0 改版」，侧栏页脚追加版本标识。

### 7.4 验收覆盖什么

`verify-wiki.mjs` 不是字符串检查，而是把产物丢进 jsdom 真跑：

- 插件是否执行、扩展数据是否真的进了 `RIFT`（技能/辅助/通货/传奇四类）
- `#exp` 是否注册成功、导航与搜索是否挂上、页面 9 个关键区块是否渲染出来
- **官方页签回归**：技能 / 通货 / 传奇 / 天赋珠宝 / 首页 五个页面仍正常，扩展没把它们弄坏
- 页面无 `undefined` / `NaN` / `[object Object]` 残留
- 无未捕获运行时异常（canvas、scrollTo 等 jsdom 缺失 API 已在测试里打桩，不算缺陷）

输出 `RESULT: ALL PASS` 才算过。
