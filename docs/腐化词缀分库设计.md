## 四、分库结构（待确认后落地）

每个槽位一个库，例如：

```
SLOT_POOLS = {
  "H": [ {k, a, b, w}, ... ],  // 头盔
  "B": [ ... ],                 // 胸甲
  "G": [ ... ],                 // 手套
  "F": [ ... ],                 // 鞋子
  "W": {                        // 武器按 wt 再分
    "bow": [...], "staff": [...], ...
  },
  ...
}
```

## 五、最终决策（已拍板）

1. **无法实现的 PoE2 词缀直接跳过**：闪避 / 混沌抗 / 抗性上限 / 属性点 / 充能 / 命中 / 荆棘 / 护体回血 / 技能速度等，本作引擎无对应维度，一律不落地。
2. **武器按 wt 细分 9 类**：bow / spear / qstaff / katana / staff / wand / crossbow / mace / jian 各自独立库，贴近 PoE2。
3. **「+1 技能等级」全归 `skillLvl`**：不分元素/类型，统一走本作已有的 skillLvl statKey。
4. **传奇专属体系暂不动**：`UNIQUE_POOL`（献祭之心）保留原样，本次不重构。
5. **替换策略保持随机**：仍从 `st ∪ mods` 均匀随机 splice 一条。

## 七、实现要点

1. `POOL` 平铺数组 → `SLOT_POOLS` 结构化表（按 slot + wt 索引）。
2. `cp(e)` 劫持改为按 `e.slot` / `e.base` 查 `pe[base].slot` / `pe[base].wt` 定位库。
3. 珠宝 `jewel` 继续走珠宝专属库（不出 skillLvl）。
4. 替换逻辑 `__uniqueReplace` 保持不变（随机 splice 一条）。
5. Wiki `loadCorruptPool()` 同步改为解析 `SLOT_POOLS`。
6. 验证脚本 `verify-corrupt.mjs` 重写池完整性断言。
