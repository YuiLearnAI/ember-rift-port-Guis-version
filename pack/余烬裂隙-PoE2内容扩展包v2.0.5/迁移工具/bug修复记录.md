## A1 时空之肌词缀数值显示错误 ✅

**现象**：tooltip 显示范围文本「将所受伤害的 5–30% 吸纳为生命」「技能冷却 -2 ~ -1 秒」，不是该件装备的固定数值。

**根因**：`temporalis` 的 `st` 是静态说明文本（图鉴/收藏也用同一字段），逐字打印，不按物品 roll；`mods` 只有 es/resAll。

**修法**（block_new.js）：
1. 定义新增 `sr: [[5,30],[5,30],[-2,-1]]`（每件 roll 一次）与 `srt` 模板（`{0}` 占位）；`st` 保留范围文案供图鉴显示。
2. 包装 `Nt`（传奇创建）：创建后按 `sr` 用游戏 RNG `re()` roll 一次存 `it.ur`。
3. 包装 `as`（物品 tooltip）：对带 `sr/srt` 的传奇，把 `st` 的范围行替换成该件 `it.ur` 解析后的固定值；旧存档缺 `it.ur` 时用 uid 派生稳定值（不消耗游戏 RNG，避免 tooltip 渲染影响随机序列）。
4. 一致性：v1.03 暗金说明已注明「除冈姆抗性上限外，特殊机制仅描述不结算」，因此没有实际战斗数值可对齐；`it.ur` 是唯一 roll 源，tooltip 与实际读取同一字段。

**回归断言**（harness_port.cjs，+5 项）：tooltip 两次渲染一致 / 每件 3 个 roll 在区间内 / 显示固定值且无范围文本 / 显示值来自同一 `it.ur` 字段 / 两件装备各显各的 roll。

**顺带修复（换基适配，非清单项）**：v0.4 的 `St(e)` 移除了第二参数（会随机选前/后缀），导致「崇高预兆·左」实际可能加后缀。新增 `StSide(e,t)`（用 base `Iv` 显式生成指定边的词缀）并在 exalt 分支使用。原回归断言「exalt+left added prefix」改为按词缀 id 差集判断新加词缀（不依赖数组顺序），修正了既有偶发失败。

## A3 消减预兆不再吃 T1 ✅

**根因**：`OmWhittle` 按每条词缀自己的 iLvl 需求表 `lv[ti]` 取最小值，跨词缀不可比（渎灵 [1,50]、skillLvl [30,55]、普通 [1..58]）；缺 ti/缺定义时 `||0` 必被吃；同刻并列时纯随机（全 T1 装备 = 随机吃一条 T1）。

**修法**：改按「刻位」排序（rank 越大越差），同刻再比 lv；无 ti/无定义词缀跳过；全 T1 返回 null，chaos 调用点兜底为「没有可消减的低等级词缀」（不删词缀、不消耗预兆）。

**断言**：whittle 只选最低刻、T1 全保留、全 T1 拒绝且预兆不消耗、无 ti 的传奇词缀永不入选。

## A4 腐烂预兆对满词缀装备失效 / 无视 3/3 上限 ✅

**根因**：`DsDesecrate` 把 `DsRoom` 词缀位置检查放在腐烂分支之前 → 满 6 词缀装备直接失败并保留原 3P3S（「结果固定」）；填充循环不分前后缀 → 产出 4~5 条后缀的非法装备；且提前 OmTake 左旋/领主等预兆却不用。

**修法**：腐烂分支上移为第一优先；`take("P",3)/take("S",3)` 严格每侧 3 条；不再消耗侧向/阵营预兆。

**断言**：满 6 词缀装备可腐烂、前后缀各 ≤3、腐烂消耗自身的预兆、不白扣死灵预兆。

## A5 深渊骨头一件装备能用两次 ✅

**根因**：只有 `t.ds`（待揭示）判断，没有每件上限；`t.dsec` 一直记录次数却从未被读。

**修法**：`DsDesecrate` 在 `t.ds` 之后加 `if (t.dsec) return "这件装备已经渎灵过 · 每件装备只能渎灵一次";`（零新增字段，旧存档自动生效；腐烂写 dsec 也一起锁）。

**断言**：二次渎灵被拒、先后缀再前缀被拒、腐烂过的装备不能再用、新装备可用。

## A6 深渊前缀池只有一条词缀 ✅

**根因**：`DsPool` 按部位过滤后非空即返回，而 ds_ 词缀 `slots` 太稀：武器/戒指前缀只有 `ds_skill`，所以前缀永远「+2 所有技能宝石等级」；部分部位前后缀池为 0/1。

**修法**：10 条渎灵词缀统一使用全部装备槽位 `DS_SLOTS = "WQSKXHBGFLRAO"`，保证每个部位每侧至少 3 条可选（同时让 A4 的 3P+3S 成立）。

**断言**：12 个装备部位各自前缀/后缀候选 ≥3；揭示始终恰好 3 个选项。

## A7 骨头通货没有关联词缀 / 解密显示不完整 ✅

## A8 深渊部分裂缝不能关闭 ✅

**根因**：`AbyssMake` 用 `Yn(room)` 随机取点，没有离墙判断；裂缝贴墙时 `Ge(i.x,i.y,30)` 刷出的 3 只 weak 怪可能卡在墙里/不可达，而关闭条件要求「裂缝 95px 内击杀」，于是击杀数凑不够、裂缝永远关不掉。

**修法**：新增 `AbyssFloorOK/AbyssWallGap`（瓦片 `M.g` 判墙、`N` 为瓦片尺寸）；裂缝取点最多重试 24 次，要求可站立且离墙 ≥28px；3 只 weak 怪刷新点同样校验地面，失败则落在裂缝本体位置。

**断言**：连续生成 12 个深渊，所有裂缝离墙 ≥20px、每道裂缝 95px 内至少有 1 只可杀的 weak 怪。

## A9 祭坛可能透明（画出来看不见）✅

## v2.0.5（2026-10-30）：吞字 / 画面突然变小黑屏

> 用户反馈的两个「必修」Bug。构建源：`block_new.js` + `build.mjs`；发布版 v2.0.5。

### B1 吞字（技能贴图/伤害数字/掉落名/提示/小地图消失）

**根因（已用插桩构建复现）**：高级通货 `mods_adv_exalt / mods_adv_regal / mods_adv_chaos` 是在
`block_new.js` 的「图标生成循环」之后才注册进 `F` 的，因此没有生成 `hr/He` 图标；这类通货掉到地上后，
基础渲染在 loot 图标处执行 `E.width`（E=hr[cur] 为 undefined）抛 TypeError。异常发生在每帧中段，
导致该帧后续的实体/特效/文字/提示/小地图全部被跳过，且每帧重复 → 表现为「吞字」。
深渊（裂缝/巨坑/保险箱）会掉这类通货，所以深渊里几乎必现。

**修复**：
1. `block_new.js` 末尾新增 `__riftEnsureCurrencyIcons()`：遍历 `Object.keys(F)` 给所有通货补齐
   9×9 图标（并写 `He` dataURL），启动时执行 + 每 3 秒自检；
2. `build.mjs` 增加「掉落图标守卫」：`hr[cur]` 缺失回退 `hr.trans`，未知底材回退 null 并跳过 drawImage；
   另加「怪物贴图守卫」：`zt[spr]` 缺失回退 `zt.zombie`，避免同类整帧中断；
3. 掉落名字 / 互动提示改为 DOM 层渲染（`#riftDomLootLabels`、`#riftObjPrompt`），画布文字层异常时仍可见；
   顺带修掉 DOM 掉落名字里引用未定义 `__sc` 的旧 bug；
4. 移除定时 `ctx.reset()`（会清空整块画布）与相关旧热修写法，改为帧首状态复位。

**验证**：插桩构建中放一个 `mods_adv_exalt` 在地面：修复前每帧 `TypeError: Cannot read properties of
undefined (reading 'width')`，修复后 0 报错；未知通货/未知底材掉落不报错、不吞字；深渊完整流程 0 报错。
`harness_port.cjs` 回归 ALL PASS。

### B2 画面突然变小 / 黑屏只剩 HUD

**根因**：视野缩放 `U0` 与画布尺寸只在 `ou()` 中计算。窗口/舞台在某个瞬间被测成很小（切屏、缩放、
全屏切换、窗口尺寸变化）时，`ou()` 会把 `U0` 定在最小值 1.2、`nt.w/nt.h` 变大，随后没有恢复，
画面就以约 1/3 大小缩在左上角、其余黑色（HUD 是 DOM，仍正常）。已用 debug 构建强制 `U0=1.2` 复现出
与用户截图一致的画面。

**修复**：`block_new.js` 的 `Vb` 包装中新增 `__riftFixView()` 每帧校验
（`ot.width/height`、`U0`、`ys/vs`、`nt.s` 与 `#stage` 是否一致），不一致立即调用 `ou()` 重建并记录到
`__riftErrors`；同时帧首统一复位画布状态；`Vb` 主绘制加 try/catch，避免单个异常让整帧状态失控。

**验证**：强制 `U0=1.2` 后下一帧自动恢复为 2.566；窗口尺寸突变/切屏/聚焦后画面正常；
引导测试 279 帧 0 异常。

## v2.0.6（2026-10-30）：符文师工匠石 / 工匠石顺序 / 背包去重

### B3 符文师工匠石无限使用 → 每件装备 1 次

### B4 先符文师再普通工匠石被误判「插槽已满」
- 根因：普通工匠石用 `rsock >= mi(slot)+extraSock` 判断，符文师加的特殊槽把 `rsock` 顶满。
- 修复：普通工匠石改为只统计普通槽 `normalUsed = rsock - specialRsock`，与 `mi(slot)+extraSock` 比较；
  普通工匠石只加 `rsock`、不动 `specialRsock`。两种工匠石顺序自由，旧存档语义不变。
- 断言（harness_new `--after`）：先符文师 → 第二次拒绝 → 普通工匠石仍成功开 1 个普通槽，ALL PASS。
