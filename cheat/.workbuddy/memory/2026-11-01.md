## v4.1 修复「T 级编号整条反了」的严重 bug（用户报告）

### 根因
`affix.ranges` 数组在游戏里是**按「弱 → 强」排列**的，**索引越大数值越高**：
- 本体 forge 面板（game.html L2047）：`h.ranges.map((x,S)=>M($e.addTier,S,"T"+(b-S)+" · "+I6(x,h)))`，`b=h.ranges.length`
  → 索引 S 的标签是 `T(b-S)`，即 `ranges[0]` 是 **T{n}（最低阶）**，`ranges[len-1]` 是 **T1（最高阶）**。
- 本体「全部升到 T1 满值」按钮（`case"allT1"`）：`r.ti = i.ranges.length-1, r.v = Pf(i.ranges[r.ti])`
  → **T1 ⟺ ti = ranges.length-1**，铁证。

我的脚本此前假定 `ranges[0] = T1`，导致整条链反了：下拉把最低阶标成 T1、把最高阶标成 T6；而「顺便升到 T1 / 一键必胜」写的是 `ti=0` = 真正的最低阶。
用户现象完全吻合：下拉里 T6 那一项显示的数值才是游戏里的 T1；勾了「升到 T1」实际升级出来的全是 T6 数值（如 manaRegen `[[10,19]...[60,70]]` 得到 19 而非 70）。

### 教训
**冒烟测试把 bug 固化了**：smoke.js 原本写着 `ok('T1(ti=0) 区间为 10~19', ...)`，照抄了错误假定，所以 78 项全绿也没拦住。
教训：断言要锚定**外部可核对的事实**（本体源码 / 真实游戏数值），不能锚定自己实现的行为；涉及"索引↔业务语义编号"的映射必须单独抽出纯函数并写对拍断言。

### 修复
- 新增统一阶层工具（放在 rangeInfo 代码块内，便于 smoke 抽取）：`tierCount(def)` / `tierLabel(def,ti)` / `topTierIdx(def)`，注释里写死本体依据，防止再次写反。
- `buildTiers()`：标签改用 `tierLabel`；下拉按 **T1 → T{n}（强在前）**排列；默认选中 T1。
- 装备页 `updateRangeHint()` 的「当前 T?」与添加成功 toast 改用 `tierLabel`。
- 保底页 ①数值拉满（`wg-t1`）：`{ti: toT1 ? topTierIdx(d) : m.ti}`、`m.ti = top`。
- ⑤一键必胜：`tierMax(d,{ti: topTierIdx(d)})`、`m.ti = top`。
- smoke.js：纠正被写反的 2 条断言，新增「阶层编号映射」10 条回归防线（含 `tierMax(manaRegen,{ti: topTierIdx}) → [70]` 直接锁死用户撞的场景）。

### 用户侧影响
旧版写坏的装备 `ti=0` 且 v=最低阶上限，**重新点一次「数值拉满」勾上「升到 T1」（或「一键必胜」）即会自动纠正**为 ti=len-1 及最强值。

### 验证
`node --check` OK；`review.js` ERROR 0 / WARN 0；`smoke.js` **91 项全通过**（原 78 + 新增 13）。

## v5 装备详情页支持「换基底（底材）」

### 本体机制核对
- `Et(baseDef, ilvl, rarity)` 生成物品：`{base: e.n, slot: e.slot, impl: q1(e), name: e.n, rsock, runes, mods}` → **base / slot / impl 三者同源**。
- `q1 = e => (e.impl||[]).map(([id,v]) => ({id, v: Array.isArray(v)?v.slice():[v]}))` —— 固有词缀完全由 `BASEMAP[baseName].impl` 决定。
- 官方修复函数 `Vp(e)` 换基底时严格限定同部位：`pe[t.base].slot === e.slot` 才执行 `e.base=t.base; e.impl=q1(pe[t.base])`。这是「为什么默认不让跨部位」的权威依据。
- 需求等级/属性需求游戏实时查 `pe[it.base]` 得到（物品不缓存该字段），所以改 base 即可自动生效；双手 ×1.5 判定 `Bw(e)` 也走 `pe[it.base].wt`，同步自动跟上。
- `aa(e)`（=GUI 的 `R.nameItem`）：rarity 0 时 `e.name = e.base`；有 `e.mi` 时用 mi 名；rarity 3 不动。故换完基底调 `refresh()` 名字会自动跟着变，无需手动干预。
- `p.equip` 结构为 `{slot: item}`；词缀定义带 `slots` 白名单时不匹配部位即为"外来词缀"（本体 forge 面板 `S.slots&&!S.slots.includes(i.slot)` 同理）。

### 实现
- 新增函数块（锚点 `/* ---------------- 换底材（改物品基底） ---------------- */`）：`makeImpl`（复刻 q1）/ `slotOf` / `baseCandidates` / `equippedSlot` / `checkBase` / `applyBase` / `foreignMods` / `baseOptsFor`。
- UI：装备详情页稀有度下方加「基底」下拉 + 「允许跨部位」开关。默认只列同部位基底（防装备槽错位）；勾选后可跨部位，已装备时自动做装备栏迁移（目标槽被占用则把原那件退回背包，背包满则拒绝并提示）。
- 换完同步 `selectedKey = 'E:' + newSlot`（否则重渲染会找不到该物品），并 toast 提示不属该部位的词缀条数。
- smoke 新增 28 项（makeImpl 结构与引用隔离、候选过滤、checkBase 拒绝路径、applyBase 三件套更新、装备栏迁移/占用/背包满、foreignMods）→ **总 119 项**。

### 踩坑
- review 的 XSS 正则 `\$\{[^}]*\.(name|nm|text|title|n)\b[^}]*\}` 会把循环变量 `b.n` 误判为「未转义的属性读取」（这是本项目第二次踩到：变量命名别用 `.n`，或先把结果存变量再插值）。
- smoke 里新增变量撞了已有同名变量（`staff`、`b0/b1`），且批量重命名脚本会误伤 fixture 的属性键 `impl:` 与 `.impl` —— 批量替换务必按锚点区段做，且排除 `.属性` 形式。

## v6 UI 重做：Apple 设计语言 + Impeccable 机器审查 + 图文教程

### 设计依据
- `VoltAgent/awesome-design-md` 的 `design-md/apple/DESIGN.md`（raw.githubusercontent.com 可直接取，562 行）。
- 核心口径： photograph-first、**全系统只有一处 drop-shadow（且只给产品图）**、单一强调色 Action Blue `#0066cc`、SF Pro + 负字距、text 17px、圆角只许 0/5/8/11/18/9999、三种背景（纯白 / 羊皮纸 `#f5f5f7` / 近黑 tile）。
- 组件映射：顶栏=`global-nav`(纯黑 44px) · 标签栏=`sub-nav-frosted`(羊皮纸80%+blur) · 内容卡=`store-utility-card`(白+发丝边+18px) · 主按钮=`button-primary`蓝胶囊 · 行内按钮=`button-pearl-capsule`(珍珠白+3px柔环) · 输入框=`search-input`(全圆角) · toast=`floating-sticky-bar`。
- **浮层不用 box-shadow**：层次感由 `backdrop-filter: saturate(180%) blur(20px)` + 96% 不透明底提供，这也正好躲开 impeccable 的「细边框+大阴影」规则。

### Impeccable（npx impeccable detect，61 条确定性规则，无需 API key）
首轮 39 项 → 修完 0 anti-patterns / 0 advisory。学到的要点：
1. **它只把 DESIGN.md 的 YAML front matter 当 palette/typography 真源**，写在正文 Markdown 表格里的 token 一律不认 → 扩展 token 必须追加进 front matter 的 `colors:` / `typography:` 段。
2. **字体栈要严格用文档里的字面串**。我自作主张加 `BlinkMacSystemFont` / `"Helvetica Neue"` 就被判 `design-system-font` 不合规，改回 `SF Pro Text,system-ui,-apple-system,sans-serif` 即通过。
3. `cramped-padding` 是静态看 `padding-top/bottom` 是否为 0：写 `height:44px;padding:0 17px` 会误伤，要显式给纵向 padding（改成 `min-height:44px;padding:13px 17px`）。
4. Apple 自己的 `ink-muted-48 #7a7a7a` 在羊皮纸上只有 **3.94:1**，不达 AA → 改用 Apple 官网真实 secondary 灰 `#6e6e73`（羊皮纸 4.66 / 白 5.07）。语义色取 Apple HIG 暗色调：error `#b00014`、warn `#9c2b00`、success `#1d6f31`。
5. alpha 派生色（`rgba(201,52,0,.06)` 之类）会被判 palette 外 → 换成预合成的实色 hex 并登记。
6. 正文连续 em-dash ≥8 且密度高会触发 `em-dash-overuse`（advisory）。
7. 教程这种长文档还会踩：`tight-leading`(行高<1.3)、`skipped-heading`(h2 直接跳 h4)。

### 工程化
- 新增 `scripts/extract-css.js`：脚本 CSS 是**唯一真源**，抽成 `docs/design/panel.css`；`--check` 模式做漂移检测，并已挂进 smoke（第 120 项断言）。
- `docs/design/preview.html`：五个页签的真 DOM 快照，既是 Impeccable 的扫描目标也是教程配图源。
- `docs/tutorial.html`：单文件图文教程（内嵌 template + JS 拼装真实面板骨架，避免贴图与实际样式走偏），含安装、五页签、阶层机制、双手倍率、换基底、保底、快照、FAQ、限制、设计附录。
- `DESIGN.md`（根目录）= Apple 原文 + 「Project extensions」段（语义色 / ink-secondary / monospace / 面板密度口径），让 Impeccable 的 design-system 检查有据可依。

## 珠宝可被腐化（保底页支持 jewels）

### 起因
用户问「珠宝不可以被腐化?」。查证结论：**官方允许**，是面板漏了。

### 本体依据（都在 game.html，已写成 smoke 断言）
- `cL()` 的 vaal 分支：`if(e==="vaal"){if(t.kind!=="item"&&t.kind!=="jewel")return"只能用于装备"}` → 珠宝放行。
- `lL()`：`if(a<.8&&e.kind==="jewel"){...cimpl...}` → 珠宝没有符文插槽，原本「+1 插槽」那一档在珠宝上改判成腐化词缀。
- `I0=e=>e&&e.kind==="jewel"?gu.filter(t=>t[0]!=="skillLvl"):gu` → 珠宝腐化池剔除 skillLvl。
- 祭坛 `$2()`：`e.kind!=="item"?"只能献祭装备"` → 珠宝拿不到第二条腐化词缀。
- `cL()` 的 frac 分支：`t.mods.length<Math.min(4,tu(t))` 且珠宝提示「需要 2 条词缀」，`tu(jewel)=su(e)`（魔法1/稀有2）→ 珠宝破溃门槛 = 稀有 + 2 条。

### 关键实现点
- **珠宝词缀是另一张表**：本体 `es`（`st()` 构造，slots 全 "J"），导出名 **`JAFF:()=>es`**，模块 Qg ∈ CL ⊂ V$。装备表是 `AFF:()=>Yt`。两表 id 不重叠（JAFF 全是 `j_*`），所以新增 `affOf(it,id)` 统一取表，禁止再直接 `AFF[m.id]`。
- **已插入天赋树的珠宝存在 `u.jw`**（10 槽），既不在 `equip` 也不在 `inv`；玩家点「插入」时游戏会把它从 `inv` 移走。`listItems()` 必须补 `J:<idx>`，否则最想腐化的那颗永远找不到。装备页「背包」筛选同步改为「背包/珠宝槽」。
- 存档侧确认安全：`Dm()` 读档是 `u=a; u.jw=Oo(u.jw)`，`jw` 里的珠宝是**完整对象**（不是 `T6()` 那种字符串编码，那条路只用于调试 `e.jewels`），所以 `cimpl` 会随角色存档一起落盘。
- UI 差异化：珠宝不显示「+1 符文插槽」选项与勾选框；祭坛整节改为说明「珠宝不可用」；一键必胜对珠宝止步于「T1 拉满 + 腐化」，不再 `payCur('ember')`、不写 `dc/cimpl2`。
