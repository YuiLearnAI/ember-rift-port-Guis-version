## 装备词缀自定义修改器（v19.x）

物品结构：{kind:"item", base, slot, ilvl, rarity(0普通/1魔法/2稀有/3传奇), mods:[{id,t:"P"|"S"|"U",ti, v:[值], ur,fr,ex}], runes:[], rsock}
- 玩家：`u.inv`(背包) + `u.equip[slot]`(已装备)

- ⚠️ 玩家对象暴露键是 `__rift.G`(=u)，不是 `inv`/`Player`/`u`！模块 m4 导出 `G:()=>u`。早期脚本误用 `R.inv` 导致永久"没进入角色"，已修正为 `R.G`。
- 词缀定义 Le(): {id,t,slots,text,stat,ranges[阶][min,max],w,lv,div,nm,pair}
- 计算属性用 `o.v[0]`（原始值）；stat 经 Da(item,id).stat 累加

- 注意：Tampermonkey 才能注入 iframe；若游戏在 iframe 内，需脚本匹配 iframe URL。也可把游戏用独立标签页打开 `https://html-classic.itch.zone/html/20171678/index.html` 后用脚本。

- 修复误用：面板 refresh 里 `updPlayer()` 映射到游戏每帧 tick a5(dt)，无参调用会让角色冷却计时器 `n.pl[c]-=undefined`=NaN；改为 `updPlayer(0)` 安全触发属性重算。
- 回档根因分析：save:()=>Xe → Yc → localStorage.setItem(pi(e),{G:u,UID}) 确实把整个角色（含 u.equip 词缀）落盘，保存有效。回档来自：① 切换/重载角色时 Dm() 用 `u=a` 整对象替换并重新读盘（仅 switch char / debug char 触发）；② 若 Tt.cur 为 null，Xe 存到槽1 而 Dm 经 Vc() 读 last/首个槽，可能错位 → 偶发回档；③ 物品详情 tooltip 快照未刷新造成的"看似回档"。建议：编辑后务必点保存、停留在藏身处片刻、勿紧接切换角色。

## v3.1 双手武器伤害倍率（面板改为「所见即所得」）
- 机制：游戏**显示与结算时**才乘倍率（`gd(e,t)= Nl(e,t)? t.v.map(x=>Math.round(x*Zg)) : t.v`），`item.mods[].v` 存的是**未乘的基值**。`Bw(e)`=双手判定，`D0(e,t)` 渲染「双手 ×1.5」标签，物品 tooltip 底部那行 `<div class="p th2">` 由 `Bw(e)&&e.mods.some(i=>Nl(e,i))` 触发。
- 官方数据（本体 _g / Dg 模块导出，无重名）：`TH_MUL`=Zg=1.5；`TWO_HAND`=Mu=`new Set(keys(OFFOK).filter(e=>e!=="none"&&e!=="jian"&&!OFFOK[e].some(t=>t!=="quiver")))` = {bow 弓, qstaff 长棍, staff 法杖, crossbow 弩}；`TH_AFF`=Fg={addPhys,addFire,addCold,addLight,physInc,spellInc,meleeInc,fireInc,coldInc,lightInc,projDmg}（11 个伤害类）；`BASEMAP`=pe；`WT`=Wt 武器类型中文名。
- `Nl` 的三个排除条件：非 kind:"item"、id 不在 TH_AFF、词缀属于 implicit（`e.impl.includes(t)`）→ implicit 不吃倍率。
- **面板改动**：数值框/下拉/区间提示统一改为显示「倍率后的生效值」，写入时 `toStoredVal()` 反解回基值。注意 `Math.round(s*1.5)` 无法用整数命中 ≡1 (mod 3) 的目标（1/3 的输入，如 100），整数回退会系统性偏高 1 → 该情况退回精确小数（4 位精度），保证填多少游戏就显示多少。
- 新增入 ____（无）；CSS 加 `.er-sev.th` 紫色标签用于标出吃倍率的词缀。
- 验证：`node --check` OK；`review.js` ERROR0/WARN0（白名单新增 TH_MUL/TWO_HAND/WT/TH_AFF）；`smoke.js` 扩到 54 项（双手判定、implicit 排除、1~400 往返一致性、越界区间换算）。

## v4 「保底」功能页：赌博类操作定向最佳结果（第四页签）
- 三处赌博机的本体实现（均已核对）：
  - 瓦尔宝珠/腐化 `lL(e,t)`：`e.corrupted=1`；`a = t?.45:E()`（传参则固定 0.45 走 impl）；a<.3 none / a<.6 impl（随机取 `ae(corruptPool(e))` → `e.cimpl={k,v}`）/ a<.8 珠宝再 impl、非珠宝 `extraSock=1,rsock+1` sock / rarity3 按 ur 重随 reroll / 否则降到稀有且只留破溃词缀。
  - 余烬祭坛 `A2(e)`（altarUse）：前置 `$2(e)` 要求 kind=item、corrupted、无 dc、余烬之心>0；命运 `Ph(e,cb)=ro(fateSeed(e)+":"+(e.ops||0))` 且 `ops++`（**确定性**：就固定由 item.fs(=z$，本身由 fsalt|uid|base|ilvl 播种)+ops 决定，故"读档无法改变"）。结果权重 20% up / 30% none / 30% down / 20% ruin（ruin 会销毁装备、返回 3-6 片余烬残片）。up 分支：追加 cimpl/cimpl2 + `mods.v = v>0? max(v+1, round(v*1.1)):v` 且 `m.ex=1`。祭坛同样行的结果显示文本表 `ALTAR_TXT`=yf。
  - 破溃 `frac`：给 1 条词缀打 `fr=true`（每件 1 条、需 ≥4 条词缀），`Vs()` 会阻止任何通货改动 fr 词缀（"破溃词缀无法被改变"）。
- 导出：`noteCraft`=Ci(kind,item,extra|null) → `item.cr[kind]++`（即 tooltip 的铸造履历），fix: kind 用 "vaal"/"altar"/货币 id。"`CORRUPT`=gu（10 条腐化词缀池），`corruptPool`=I0(item)（珠宝自动剔除 skillLvl），`BENCH_CUR`=Fh，`CRAFT`=_a。
- **游戏 bug**：腐化词缀显示表 `C3` 缺 `skillLvl`，`Wa=(k,v)=>(C3[k]||k+" {v}")` 会把它显示成 "skillLvl 1"。面板用自己的 CIMPL_TEXT 覆盖（10 条全有中文名），smoke 里有断言守着。
- 面板实现要点：无法注入随机性（没导出 RNG），故按源码"最好分支"复刻并把随机挑选改成用户自选；每次操作前 snapAuto 快照、`noteCraft` 写履历、默认不扣通货（勾选项 payCur 模拟消耗）。新增维护区可撤销 dc/cimpl/cimpl2/腐化/ex/fr，便于反悔重来。
