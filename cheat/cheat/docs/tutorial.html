余烬裂隙 修改器

一个悬浮在游戏页面上的侧边面板，用于修改通货、自定义装备词缀、锁定赌博类操作的结果，并在动手前自动留好退路。

开始之前

它是浏览器里的一个用户脚本，通过读写游戏自己的存档键来工作。先确认三件事，能省掉后面九成的困惑。

它改的是「游戏自己的存档」

通货写入 localStorage['ember-rift-wallet']，角色与背包写入 localStorage['ember-rift-save-v4']（明文 JSON）。面板从不做网络请求，也不需要任何账号。

必须先进角色

脚本靠游戏暴露的 window.__rift 取数据。只有进入某个角色、真正加载到世界之后它才存在。停留在标题界面时，状态页会一直提示未就绪。

改之前先看两眼

所有会改动物品的操作都会自动留下快照（localStorage['er-snapshots']，最多 5 份）。真改坏了就去「审查」页还原。但请不要在改完一件装备后立刻切换角色，这是已知最容易丢失改动的场景，详见常见问题。

安装

  1. 安装 Tampermonkey 扩展（Chrome 应用商店搜 Tampermonkey，或任选同类的用户脚本管理器）。
  2. 打开 Tampermonkey 控制面板，选择「添加新脚本」（实用工具页）。
  3. 把仓库里的 ember-rift-gui.user.js 内容完整粘贴进去，覆盖模板里原有的全部内容。
  4. Ctrl+S 保存，确认开关是启用状态。
  5. 打开余烬裂隙的游戏页面。脚本注册了两个匹配地址，分别是 itch 的外层页面和实际跑游戏的 html-classic.itch.zone 内层框架，面板会出现在内层页面上。
  6. 进一个角色，等右上角出现面板即可。

面板没出现怎么办

先确认不是停在主菜单；然后刷新一次页面。window.__rift 是在游戏加载过程中挂上去的，脚本会轮询 8 秒，超时就放弃注入，刷新即可重试。如果依旧没有，去「状态」页看它给出的具体原因。

界面导览

面板自上而下分三层：黑色标题栏、毛玻璃标签栏、内容区。标签栏固定五个页签。

页签用来做什么
通货按游戏自身分组折叠浏览 34 种货币，按官方估值分档补给，或逐行设成任意数量。
装备浏览背包与身上的装备，改稀有度、换基底、增删改词缀。
保底让工艺台、瓦尔宝珠、余烬祭坛这些掷骰子的操作，每次都走到最好的那一档。核心功能
审查体检存档里的非法数据，以及存放、还原快照。安全网
状态看脚本和游戏的连接状态，用于排查面板没出现等原因。

① 通货

34 种通货按游戏自身的分组折叠陈列，想改哪种就展开哪一种；给多少按官方估值分档，不会一次性把所有货币灌到满。

给多少：按官方估值分四档

补给量不是拍脑袋定的，而是用官方资料里每颗通货的估值（以混沌石 c 为单位）分档：越值钱的，一次给得越少。

档位估值 v少量适中充足游戏里的例子
常见≤ 0.5 c1040120蜕变石 0.02 c · 灼热符文 0.5 c · 改造石 0.06 c
少见≤ 3 c51560混沌石 1 c · 瓦尔宝珠 1.5 c · 苦难精华 2.5 c
稀有≤ 60 c138崇高石 12 c · 破溃石 60 c · 三种印记 25 c
珍贵> 60 c125神圣石 120 c

三档全部补给的总量参考：少量 205 颗（≈487 c）· 适中 764 颗（≈1383 c）· 充足 2417 颗（≈4075 c）。数字由 scripts/smoke.js 用 game.html 的真实 CUR 表算出。

还想一次拉满怎么办

面板刻意不再提供「全部拉满 99999」——那会让通货运筹形同虚设。但每行输入框没有上限：填 99999 再点「设」，效果与过去完全一样，只是现在它是你主动的选择。

简介模式：把官方资料搬到眼前

点显示简介，每行会多出一行说明：掉落占比 / 获取途径 · 估值 · 这颗通货的作用。

名称与分组直接取自游戏数据（R.CUR 与 R.CUR_GRP），所以和你在游戏仓库里看到的名字完全一致，不会因为版本更新而对不上。改动会写入 localStorage['ember-rift-wallet']，刷新后仍在。

② 装备

进页是列表，点一件进去是详情。列表支持按名称、部位、稀有度筛选，也能筛「只看身上穿着」。

详情页能改什么

数值框里填的是「游戏里看到的那个数」

这里最容易出错的地方是：游戏在物品里存的是没乘倍率的基值，显示和结算时才乘上去。面板替你做了换算，你填多少，游戏面板就显示多少，不需要自己做乘法。

词缀阶层是怎么回事

这是最容易搞错的一处，务必先看这一节。

游戏内部把每种词缀的数值范围，按由弱到强排成一个数组：ranges[0] 是最低阶，最后一个才是最强的 T1。这一点在游戏自己的 forge 面板里有明确写法（标签是 "T"+(总数-索引)），而「全部升到 T1」按钮用的正是最后一个索引。

因此本面板的下拉按 T1 在上、依次往下 排列，并且默认就停在 T1，也就是最强的一档。

曾经犯过的错

早期版本把 ranges[0] 当成了 T1，结果下拉整个反了：看起来叫「T6」的那一项，才真正是 T1 的数值；勾选「升到 T1」实际却写成了最低阶。现已修正，并在自动化测试里加了专门的对拍断言防止复发。

双手武器的 1.5 倍

同数值的一条词缀，装在双手武器上会比单手多一半，这是游戏自身的规则。

游戏在显示和结算时才乘 1.5，物品里存的是没乘的基值。触发条件是三样同时成立：物品是双手武器（长棍、法杖、弓、弩）、词缀属于那 11 种伤害类、并且这条词缀不是底材自带的固有词缀。

面板会做两件事:

  • 详情页顶部出现注意提示,明确写出这是哪种武器、倍率多少。
  • 享受倍率的词缀行右侧标一个 ×1.5 小标签,让你一眼分清哪些吃了加成。

换基底时这两个标识会同步更新，因为是否算双手取决于底材的武器类型。

为什么填 100 有时显示 101

基值要先乘 1.5 再取整，某些目标值（整数除三余一的那批）用整数基值恰好够不到。面板遇到这种情况会退回到精确小数存储，保证你填多少就是多少。

③ 换基底新功能

在详情页可以保留全部自加词缀的前提下，把这件装备换成同部位的另一种底材。

基底在游戏里同时决定了四件事：部位、底材自带的固有词缀、需求等级，以及是否算双手武器。游戏的需求等级是实时查表得来的，所以换完 base 之后，其余这些都是自动跟上的。

换基底时会发生什么

  • 固有词缀按新底材重新生成。这是不可避免的，因为固有词缀本来就由底材决定。
  • 你自己加的词缀全部保留，面板只动 base、slot、impl 三项。
  • 名字会跟着更新：普通装备直接跟随底材名，魔法与稀有会重新生成名字，传奇名不动。
  • 换完之后如果有个别词缀不属于新部位（游戏会给某些词缀限定部位），提示条会告知条数，去「审查」页可以看到具体是哪几条。

为什么默认不允许跨部位

游戏官方自己的修复逻辑也只在「部位相同」时才敢换底材，这个限制是有依据的。跨部位会让装备槽错位，所以默认锁住。真的需要时勾选开关即可：背包里的物品直接换，已经穿在身上的会自动挪到新部位，新部位如果已经有东西，那件会被移回背包；背包满了则拒绝执行，避免弄丢装备。

④ 保底：让掷骰子的操作每次都走最好结果

工艺台、瓦尔宝珠、余烬祭坛的结果在游戏里是随机的，而且随机源写在游戏内部、没有外部入口可以替换。所以这里的做法是：按官方源码把「最好的那个分支」完整复刻一遍，再把原本随机挑选的部分改成由你自己指定。

原版结果保底后
瓦尔宝珠：无事发生 / 加一条随机腐化词缀 / 开槽 / 降级固定给出腐化词缀，且词缀由你挑、数值拉满
余烬祭坛：升华 20% / 无事发生 30% / 失衡 30% / 化为余烬 20%锁定升华：追加一条你选的词缀，全部词缀 +10%（可超越 T1）
神圣石：数值随机重掷直接顶到当前阶层上限，或一步到 T1

珠宝也在这一页：可以腐化，但没有插槽与祭坛

官方对瓦尔宝珠的判定是「装备或珠宝」，所以天赋珠宝同样能腐化、能拉满、能破溃。三处和装备不同，面板会自己切换：

  • 没有「+1 符文插槽」。游戏里珠宝走到这一档时会改判成追加腐化词缀，所以面板直接去掉这个选项。
  • 腐化词缀池少一条。官方会剔除「技能等级」，因为珠宝上它没有意义。
  • 没有余烬祭坛。祭坛只接受装备，珠宝拿不到第二条腐化词缀；「一键必胜」对珠宝也止步于腐化。

已插入天赋树的珠宝也会出现在目标列表里（游戏插入时会把它从背包移走，存放在天赋树自己的槽位数组里），不需要先拆下来。

维护区：做错了也能退回去

底部还有几个按钮，用来撤销双重腐化、清除全部腐化标记、清除超越标记、清除破溃标记。它们对应的是物品上的几个状态字段，清掉就能重新执行一次操作。

⑤ 审查与快照

「审查」页做两件事：给存档做体检，以及保管你的退路。

快照只是另一把钥匙

快照存在独立的 localStorage 键里，绝不会去覆盖游戏的存档键，也不会因为清理浏览器数据以外的原因消失。还原采取原地把内容写回的方式，这样游戏内部那个指向当前角色的引用依然有效。

常见问题

为什么有时候改动会回档？

主要有三种情况：

  • 切角色。游戏的读档是把整个玩家对象重新赋值。刚改完就切角色，内存里的改动还没来得及落到磁盘就被覆盖了。改完后在藏身处待一会儿，别紧接着切换。
  • 钱包数量变空。通货那一块的写法和存放位置有关，数量为空时槽位会对不上，出现「改了显示没错，重进却变了」的错位。
  • 看着像回档，其实是提示没刷新。游戏装备悬浮提示是打开那一刻的快照，你在外部改完 mods 它并不会自己重画。关掉重开，或者刷新页面再看。

这三种里只有前两种是真的丢数据，也正是快照存在的意义。第三种纯属虚惊。

为什么地图、兽魂、珠宝的词缀改不了？

它们用的是各自独立的一套词条表，和装备的词缀表并不通用。更关键的是，地图那条统计函数在内部取值时没有空值保护，硬写进去会让游戏读取时直接抛错。所以这三类的词缀只提供只读查看。

但「只读」只针对增删词缀：珠宝的腐化、数值拉满、破溃在「保底」页可以照做，因为那几项只往物品上写状态字段，不需要往珠宝里塞装备词缀。地图与兽魂没有这层例外——官方本来就不给它们腐化，面板也不会替你绕过。

添加词缀时数值能不能超过区间？

可以。超出区间只会给出越界提示，仍然照写。这类数值通常还是生效的，但要留意个别词条在极端值下的表现。

面板找不到刚放下的装备？

列表会遍历穿着中的装备、背包（含地图/兽魂/珠宝），以及已经插进天赋树的珠宝。物品是否进背包受容量限制：背包 160 格，地图袋 120 张，宝石类不占格也不设上限。放不进去时是游戏自己拒绝的，不是面板的问题。

已知限制

  • 地图、兽魂、珠宝的词缀只读（珠宝仍可在保底页腐化/拉满/破溃）。
  • 回档无法百分之百杜绝，只能靠快照把损失降到最低。
  • 3 秒内的连续编辑会合并为同一个快照，想分步保留请手动「立即存快照」。
  • 游戏内部随机生成的结果无法预知，本面板提供的是「由你指定目标值」而不是改写随机源。
  • 背包 160 格、地图袋 120 张的限制来自游戏本体，面板不会绕过。

附录：设计与审查

界面按 awesome-design-md 里的 Apple 设计语言重做，并用 Impeccable 做了一轮机器审查。

组件怎么对应的

面板部位Apple 组件关键取值
标题栏global-nav纯黑底、44px 高、12px 白色文字
标签栏sub-nav-frosted羊皮纸 80% + 背景模糊
内容卡store-utility-card白底 + 发丝边框 + 18px 圆角
主按钮button-primaryAction Blue 全圆角胶囊
行内小按钮button-pearl-capsule珍珠白底 + 柔环边框
输入框search-input全圆角胶囊

两条铁律

  • 全系统零投影。Apple 整个系统里只有一处阴影，且只给放在台面上的产品图。这里浮层的层次感由背景模糊加 96% 不透明底提供，不用阴影。
  • 单一强调色。所有可点元素只用 Action Blue，不引入第二个品牌色。语义红橙绿仅用于状态表达。

Impeccable 审查结论

首轮共报出 39 项问题，集中在两处：次要灰在羊皮纸底上对比度只有 3.9 比 1，以及标题栏纵向缺少内边距。处理如下：

  • 次要文字改用 Apple 官网在用的 secondary 灰 #6e6e73，各处均达到 WCAG AA。
  • 语义色加深为 Apple HIG 系统色的暗色调（橙 #9c2b00、绿 #1d6f31），连带把告警区底色上的文字也一起拉过达标线。
  • 字体栈严格改成设计文档里的字面定义，去掉了自作主张添加的备选字体。
  • 补充的设计 token 全部登记进项目根目录的 DESIGN.md，让检查有据可依。

复检结果：0 anti-patterns，0 advisory。可用 npx impeccable detect docs/design/preview.html 自行复现。

文件都在哪

  • ember-rift-gui.user.js：用户脚本本体，也是样式的真源。
  • DESIGN.md：设计要求文件，Apple 原文加上本项目的扩展 token。
  • docs/design/preview.html：面板预览，供 Impeccable 检测与配图。
  • scripts/extract-css.js：把脚本里的样式抽成 docs/design/panel.css，保证预览与线上不会走偏。
